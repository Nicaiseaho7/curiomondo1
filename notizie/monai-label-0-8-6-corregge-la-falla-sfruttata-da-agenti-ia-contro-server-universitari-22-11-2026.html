MONAI Label 0.8.6 corregge la falla sfruttata da agenti IA contro server universitari

La nuova versione chiude una scrittura arbitraria di file; le installazioni esposte prima dell’aggiornamento devono essere controllate per accessi già avvenuti

Il progetto MONAI ha pubblicato il 22 novembre la versione 0.8.6 di MONAI Label, pacchetto usato per annotare immagini mediche con strumenti di intelligenza artificiale. La distribuzione su PyPI arriva dopo la scoperta di una vulnerabilità critica di attraversamento dei percorsi che permetteva di scrivere file fuori dalla cartella prevista.

La falla, identificata come CVE-2026-133968, interessa le versioni fino alla 0.8.5. Un parametro controllato dall’utente nell’endpoint di caricamento veniva unito al percorso del deposito senza verificare che la destinazione rimanesse nella directory autorizzata. Un attaccante raggiungibile in rete poteva così collocare file dove il processo aveva permessi di scrittura.

Amazon Threat Intelligence ha ricostruito un attacco di settembre contro università dell’Asia orientale. L’operatore aveva affidato a più agenti del framework Cairn l’obiettivo di ottenere una shell. Contro un server MONAI Label, gli agenti sono passati dalla mappatura delle API alla scrittura arbitraria in circa undici minuti e, in una sessione successiva, hanno ottenuto controllo con privilegi elevati.

L’attribuzione a un attore collegato alla Cina deriva da lingua dei comandi, fuso orario degli script e altri elementi osservati nell’istanza Cairn lasciata pubblicamente accessibile. Amazon non identifica le università e non afferma che dati clinici o di ricerca siano stati sottratti. Questi limiti impediscono di estendere l’incidente a tutte le installazioni del software.

PyPI registra il file monailabel-0.8.6 come caricato il 22 novembre. L’aggiornamento contiene la correzione che confina i percorsi e aggiunge controlli anche sull’estrazione di archivi di sessione. La sola installazione della nuova versione, però, non rimuove un eventuale accesso ottenuto prima della patch né cancella modifiche già eseguite sul sistema.

Gli amministratori devono aggiornare, limitare l’accesso da reti non fidate, attivare l’autenticazione e far funzionare il servizio con privilegi minimi. Per server precedentemente esposti servono conservazione dei log e ricerca di file inattesi o processi anomali. L’incidente documenta una capacità concreta degli agenti offensivi, ma non dimostra autonomia completa: obiettivi e bersagli erano forniti dall’operatore.
