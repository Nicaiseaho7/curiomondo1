GitHub apre alle API le impostazioni di Copilot code review

REST e GraphQL ora gestiscono policy dall’impresa al repository e attribuiscono in modo esplicito commenti e fonti.

8 novembre 2026 alle ore 13:30 · 2 min di lettura

A cura della Redazione CurioMondo

GitHub ha annunciato il 6 novembre nuove API per leggere e modificare le impostazioni di Copilot code review, dalla policy enterprise al singolo repository. Le risposte possono identificare esplicitamente recensioni e commenti generati da Copilot, indicare il livello di effort e riportare skill, server MCP e istruzioni personalizzate dichiarati come fonti.

La tracciabilità aiuta audit e automazione, ma la lista delle fonti dichiarate non prova che ogni suggerimento sia corretto. GitHub ha anche reso più compatto il commento riepilogativo e corretto problemi di fatturazione, revisioni automatiche e affidabilità. La funzione è disponibile sui piani Pro, Pro+, Max, Business ed Enterprise.

I team italiani possono applicare policy uniformi e separare commenti umani da quelli dell’IA. Nei progetti regolati è utile conservare metadati e decisione finale del revisore. L’automazione non deve diventare un’approvazione implicita: merge e rilascio restano responsabilità del team, soprattutto per autenticazione, privacy e pagamenti.

Prima di attivare modifiche automatiche su molti repository, gli amministratori dovrebbero testare permessi e rollback. Sarà importante misurare commenti utili, falsi positivi e tempo risparmiato. Le API facilitano il controllo centralizzato ma aumentano l’impatto di un token amministrativo compromesso, che va protetto e ruotato.
